# План развития SlotGuard

SlotGuard становится рабочим пространством для команд, которые делят помещения и оборудование. Участник видит доступность и управляет своими заявками. Администратор ведёт каталог и планирует обслуживание. PostgreSQL остаётся источником данных для календаря, очереди и метрик.

- [x] **Обзор организации.** Добавить недельную сводку и загрузку по дням через `GET /api/workspace/overview`. Проверить расчёт по ресурсам текущей организации.
- [x] **Личный кабинет.** Добавить предстоящие брони, резервы, лист ожидания и завершённые сеансы через `GET /api/workspace/me`. Проверить выборку по владельцу и организации. Подтверждение, отмена и выход из очереди используют действующие маршруты.
- [x] **Каталог ресурсов.** Добавить создание и редактуру ресурсов, архивирование и восстановление через админские маршруты `/api/workspace/resources`. Проверить права доступа, историю после архивирования и конфликт архивирования с будущей бронью.
- [x] **Плановое обслуживание.** Закрывать несколько слотов одного дня одной транзакцией через `POST /api/maintenance/window`. Проверить, что при конфликте API возвращает точные интервалы и сохраняет остальные слоты в прежнем состоянии.
- [x] **Журнал действий.** Сохранять изменения каталога и обслуживания вместе с основной операцией. Проверить изоляцию, права чтения и записи после успешных операций.
- [x] **Интерфейс и выпуск.** Связать обзор, календарь, личный кабинет и управление. Проверить вход, переключение организации, навигацию, бронирование и обслуживание в браузере. Проверено отображение на широком и мобильном экранах, пройдены 16 интеграционных тестов.

Планирование опирается на [Writing Plans](https://github.com/obra/superpowers/blob/main/skills/writing-plans/SKILL.md). Для реализации использованы [Karpathy Guidelines](https://github.com/multica-ai/andrej-karpathy-skills/blob/main/skills/karpathy-guidelines/SKILL.md), для интерфейса — [Frontend Design](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md).
